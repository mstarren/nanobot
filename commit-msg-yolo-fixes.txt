fix(approval): make yolo mode session-scoped, single-line pill, HITL label

Addresses three issues with the yolo-mode composer pill (PR #6):

1. Session-scoped yolo mode. The runtime toggle was a single process-wide
   boolean, so enabling yolo in one chat auto-approved gated calls in every
   chat. ApprovalGate now keeps a per-session override map
   (`yolo_sessions`) alongside the config default (`yolo_mode`); the hook
   checks `yolo_mode_for(session_key)` and the WebUI mutation
   `/api/approval/yolo` accepts an optional `session` key to scope the
   toggle. The settings payload reports both the default and the overrides,
   and the composer pill state is tracked per session key in the WebUI.

2. Single-line pill. The YoloModePill button was a plain inline-block
   button whose inline children could not truncate under the composer's
   container-query compression. It is now `inline-flex items-center
   justify-center overflow-hidden whitespace-nowrap` with a truncating
   label span, so icon + label always render on one line and ellipsize
   instead of wrapping/overflowing when space is tight.

3. HITL label when off. The pill now reads "HITL" (human-in-the-loop)
   while yolo mode is off and "YOLO" while on, via a new
   `thread.composer.yolo.labelOff` i18n key added to all 10 locales.

The hardline DENY floor still applies in yolo mode and is never bypassed.
